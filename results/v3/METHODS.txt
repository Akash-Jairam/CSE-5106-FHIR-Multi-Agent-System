Analysis protocol recorded 17 October 2026
Reporting presentation revised 19 October 2026

Purpose
Consolidate the development Single Agent and V3 arms (300 questions each) and
the full benchmark comparison (2,929 completed task pairs from 94 patients).
All primary full comparison accuracy, time, token and cost figures use that
same denominator for both systems. Historical execution records remain
unchanged. Derived tables, archives and the handoff document are additions on
results/v3-ful-run.

Primary comparison
We ran both systems against the full benchmark and report comparative results
for 2,929 completed task pairs. Pairing joins accepted question IDs and verifies
patient IDs. Selection is posthoc by completion, without selecting by
correctness. Runtime failures are not scored as wrong answers and their
measurements do not enter design totals. comparison_summary.csv provides the
primary reporting figures; its V3 row comes from matched_v3_summary.json.

The released benchmark and original V3 execution archive contain 2,931
questions. RUN_REGISTRY.json and run_summary.csv retain historical execution
counts and completion status. The 2,929-pair reporting view leaves those source
records and original completion gates unchanged.

Acceptance and measurement
Full-arm records use the frozen first-clean-attempt selection. Only selected
accepted task latency and usage enter design accuracy, time and cost summaries.
Discarded task attempts are internal operational records and are not added to
the design totals. Correctness uses the existing deterministic typed-answer
scorer, without an LLM judge, prompt changes or additional inference.

Development records retain their historical first-attempt protocol and frozen
scores. They are not silently reprocessed to match the later full-run policy.
Unknown development whole-question usage remains missing. Observed-only
summaries always state the observed denominator; a partial observed sum is not
a complete total. The original 300-question development cohort is reused and
overlaps the full benchmark. Do not pool those rows or treat the four records
as four independent experiments. Development-patient exposure comparisons are
descriptive because design refinement had access to those patients.

Model and source identity
The runs use the recorded Azure deployment of gpt-6-luna with reasoning none.
Frozen full-arm settings include a 16,384-token completion limit, 200,000-token
question budget, 30-tool-call budget, a 32,000-token input guard, enabled prompt
caching, SDK timeout 60 seconds, SDK retries zero, and two worker processes.
Use the manifests for the authoritative settings and source identities.

Cost
Use frozen OpenAI-rate proxies authorized by the user: input USD 0.10 per
million tokens, cached input USD 0.01 per million, output USD 0.50 per million.
For measured prompt P, cached prompt K and completion C:
  estimated USD = ((P - K) * 0.10 + K * 0.01 + C * 0.50) / 1,000,000.
Cached tokens are a subset of prompt tokens. Actual provider invoices and
reported dollar costs are unavailable; proxy values are estimates. A numeric
zero after normalization is not by itself proof that original cache metadata
was present. Source cache audits and their coverage are preserved separately.
No-cache sensitivity sets K to zero while keeping measured P and C fixed; it
is an accounting scenario, not another model run.

Statistics
Export each question's score and available latency, usage, cost, tool, evidence
and mechanism diagnostics. Numeric summaries include observed/missing counts,
totals where complete, mean, median, sample standard deviation, p95, minimum
and maximum. Development tables additionally contain other saved quantiles.
Patient-cluster percentile bootstrap intervals use 10,000 replicates and seed
5106. Resample patients, retain all their questions and compute question-weighted
means; paired intervals preserve the within-question arm pairing. Full analyses
sort FHIR patient identifiers as strings. Newly derived development measurement
intervals sort their local numeric patient-cluster labels numerically; the exact
analysis source preserves that Monte Carlo ordering. Do not
interpret these intervals as uncertainty over repeated model runs or providers.

The paired_comparison files use Single Agent minus V3, as their left/right
fields specify. The main handoff uses V3 minus Single Agent and reverses those
signs. Ratios compare aggregate means or totals on the same complete cohort,
not averages of individual ratios. Subgroup comparisons are exploratory and
are not adjusted for multiple comparisons. Frozen exposure labels refer only
to the original split's dev/pilot patients. All 58 patients in the later fresh
300-question development run are labeled held_out_patient_descriptive by that
older split; they contribute 1,678 matched full questions. The known union of
original dev/pilot and later fresh-development patients is 93 of 94 patients.
Consequently, these source-split labels must not be presented as an untouched
test group. Exploratory overlap records preserve this distinction explicitly.

Interpretation
Latency is task elapsed time. Sum of task latencies is not wall-clock duration
when workers run concurrently. Measured cost includes repeated prompt usage;
repeated-prompt heuristic values are descriptive and are not added again.
The heuristic sums min(current prompt, preceding prompt plus completion) within
the analyzer's phase sequence; it is not an exact text-overlap or cache-hit
measurement. Evidence validity and source-check flags express local recorded
checks, not independent clinical correctness. Empty-answer flags are syntactic:
a correct empty reference answer can also carry that flag.

Single Agent and V3 were run on different dates without randomized interleaving.
Observed cache differences affect dollar and latency comparisons. The present
data support conditional benchmark findings, not a causal architecture-only
claim or a claim of clinical deployment readiness. The development and full
sample sizes, source-bound difference, reused cohort and accounting assumptions
must accompany any report or presentation figures.

Preservation
Original benchmark directories and source commits are retained for provenance.
Portable archives preserve canonical result fields, model/tool traces and owned
audit payloads. Archive manifests describe byte preservation and reconstruction.
Canonical JSON whitespace and original gzip headers are not implied to survive
reserialization. Clinical benchmark content belongs in the private repository.
Internal operations are separate from the design analysis and main report.
