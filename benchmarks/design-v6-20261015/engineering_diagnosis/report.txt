Assurance and plausible bounded hypotheses
The frozen B prompt states the full worker mapping is available beyond its preview and explicitly forbids a second execution/feedback. Execution returns detailed errors, but the generator never receives them. Actual Single has a full five-variable example and ordinary execution/source-feedback continuation; B has textual contract guidance and one shot. A generic auxiliary-specific native schema/example and explicit workspace Type→list / full-Type-id / worker-library interface could therefore improve contract compliance. A bounded repair experiment could expose actual missing-variable, ID, import and runtime errors without A or gold, re-execute, then apply the unchanged original source gate. Such an experiment must predeclare how the same25k/3tools/2calls funds repair versus selection; feedback is not free, and patching a result without execution/source checking is not equivalent.
Packet coverage is a separate hypothesis: inspect lossless representation/reservation composition before any cap change; do not silently drop A/B code, necessary evidence, or complete context. No evidence here justifies granting B more budget, ignoring limitations, relaxing the shared source checker or declaring held retrieval complete.
