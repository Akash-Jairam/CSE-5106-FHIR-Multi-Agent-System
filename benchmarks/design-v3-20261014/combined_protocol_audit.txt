Operational changes

The driver supports explicit --audit_storage inline|gzip. The subset launcher
defaults to inline and forwards a selected mode; the full supervisor defaults
to gzip. Team strategy and storage mode are independent: stable result arm
filenames remain unchanged while identities pin the actual multi_agent_v3
strategy, storage mode, artifact schema and source fingerprint. The full public
manifest also records the selected team strategy.

All workers can preserve complete returned traces, retrieved_fhir_resources
maps and revision.messages in content-addressed, timestamp-free gzip JSON
artifacts before returning results across IPC. The V3 worker consumes the same
optional include_full_audit and audit_context tuple fields as the legacy worker,
uses the common output wrapper, then the common lossless externalizer. The
parent stores the same reference idempotently before Pandas accumulation.
Answers, exact evidence (including optional paired scope_index), limitation,
resource IDs, tool calls, token/cost/budget data, and revision outcomes stay
inline. Empty list placeholders plus audit_artifacts retain field types. This
does not change model inputs, prompts, field semantics, tool behavior, scoring,
or the original agent latency boundary. The artifact codec improves provenance
by retaining raw returned workspace maps that the frozen V2 driver dropped.

The artifact descriptor pins schema 2, codec, owning question, allowed relative
path, exact stored fields and uncompressed SHA-256. Atomic writes avoid partial
artifacts. Explicit restore_result_audit reconstructs the complete returned
audit, including historical attempts, field order and all message/code strings.
Restoration validates owner/path/hash and has a 512 MiB per-question safety
limit; data is never truncated. Missing/corrupt references refuse resume before
any model call. Legacy trace-based diagnostics must deliberately restore audit
fields; compact accuracy/token/revision metrics do not require restoration.
Streaming result-array validation avoids reloading the complete temporary JSON.
Full supervision remains first-attempt only, with no automatic retries, immutable
manifest/source checks, clean process-group termination, and partial-run alerts.

V2 audit-retention correction

Frozen V2 parse_outputs retains resource ID maps and complete returned tool and
message traces, but drops the raw returned retrieved_fhir_resources workspace.
Its frozen design prose claiming all retrieved inputs were retained therefore
overstates saved workspace coverage. Append that correction to the V2 outcome
record without rewriting the frozen design. Gzip preserves future returned maps;
it cannot recover an already lost workspace or one an exception never returned.
