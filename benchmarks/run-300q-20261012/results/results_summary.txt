Midterm benchmark results

This is a frozen subset study of the published FHIR-AgentBench dataset. The ordinary evaluation covers 300 held-out questions from 58 observed patients, answered by each of three systems (900 attempts). Recovery evaluates 50 questions per system/condition from 27 observed patients (single and multi-agent × intact and omitted packets = 200 attempts). Variability uses the same 20-question subset in five repeats per system (300 attempts). All 22 arms and 1,400 first attempts are covered.
Every system uses one base model, gpt-6-luna, through azure; reasoning effort none. Per-question ceilings: 200,000 tokens and 30 tool calls. The tool cache is shared.
Typed reference-value matching accuracy, released-answer diagnostics and primary usage describe the first recorded attempt. Failed attempts count as wrong; a later retry cannot improve the benchmark score. Intervals are patient-clustered 95% percentile bootstrap CIs (10,000 resamples, seed 5106); differences are paired on identical questions.
The frozen typed scorer does not consult limitation or budget-stop flags. A null/empty prediction matching an empty reference ([] or [[None]]) can count correct even when produced by a budget stop, abstention or unverified withholding. Primary reference-value matching accuracy therefore does not establish supported empty answers. Evidence-backed correct empty-reference counts are reported separately below from empty_reference_verified.

Provenance and limitations
  GitHub source: https://github.com/Akash-Jairam/CSE-5106-FHIR-Multi-Agent-System at d87ae5a2e7d7e57fceeb17b88e5b9d877b15361c.
  Local pilot fixes: Final role response after last tool; clarify Python return contract. Based only on pilot data. 102 regressions passed.
  Local patch SHA256: f6b5d9de273f33974c7733275f8041dec9537d90cc5c40fd1d0bbeab2975be0e; evaluated code fingerprint: f1076723fc34b911c4fd2dec9eb8d9689122bb418445df86cbe7f272e58f1276.
  Pipeline corrections were made using pilot data before this held-out run; the evaluated implementation includes those local changes. This batch was not used for outcome-driven tuning.
  This eligible subset study does not reproduce the full published benchmark or establish clinical effectiveness. This first full batch checks the current implementation and does not establish research superiority. Family and recovery comparisons are exploratory and CIs are not adjusted for multiple comparisons. Constant outcomes can yield zero-width bootstrap intervals. Five repeats on 20 questions give coarse variability estimates (one question is five accuracy points). Shared cached records do not make model/provider execution deterministic.
  Missing metric coverage is disclosed above. Primary token means require all contributing question usage; latency summarizes only measured attempts. Recovery counts use known metadata denominators; unknown use/fetch metadata is not counted as failure or success.
  A shared implementation guard rejects individual input prompts above 32,000 tokens, separately from the 200,000-token aggregate ceiling. Large accumulated contexts, including the single-agent baseline, can fail at this guard before reaching the aggregate ceiling. These errors are implementation-limit observations, not measurements of the provider context limit; they remain wrong first-attempt outcomes. Aggregate ceiling stops are recorded separately as budget stops.
  Completion and numeric consistency were checked from aggregate reports and final health. Current input/code/settings identities must also pass the repository status gate.
