V7 / selected H2: adversarial offline test plan
Status: prospective test plan only; no implementation, inference, dataset access, scoring, promotion, or accuracy claim.

Purpose and fixtures
Use synthetic questions/resources and the actual SingleAgent.run loop. Patch credential setup, starting-packet/retrieval/checker boundaries and provider sends; never load private Settings/configuration. Most tests supply deterministic native SDK-style responses plus canonical per-call usage. At least one worker integration must exercise the actual frozen source-check/execution/output serialization boundaries with synthetic records. No real question, answer, SQL, historical raw result, FHIR request, or network access is needed.

The baseline oracle is a fresh actual SingleAgent with its unchanged prompt, default 30 iterations, 200,000 token cap and inclusive 30 tool cap. H2 A must have exactly the same natural policy. It is not V6 ContinuousPrimary's 175,000/27 policy or LedgerSolver. Compare both observable requests and final normalized output; a mocked top-level return alone cannot prove loop parity.

Contract to pin before implementation tests
- A runs naturally with full aggregate caps; no selector reservation, early handoff, forced final, budget nudge, local cap reduction, altered retrieval or prefix is inserted into A.
- Aggregate caps: 200,000 reported total tokens, 30 charged tools, 30 admitted SDK requests/attempts across A, B and selector. Unknown usage or actual post-provider overshoot is fatal even after a valid A. A known pre-admission budget refusal is not an SDK send or an unknown billed attempt.
- After A: R_T=200,000-T_A; R_U=30-U_A; B iterations=min(30,30-C_A-1). Do not give B a hidden fresh global budget. If callers impose lower caps, the same arithmetic uses those effective aggregate caps; it never raises them.
- B initialization is one extra host tool, charged exactly once when its original starting-packet initialization is actually invoked, including initialization failure. A/control initialization remains excluded equally. No duplicate prefetch. Entry requires R_U>=3 and at least two B model slots plus one selector slot. B's native inclusive tool cap is R_U-1; its starting-packet tool is outside that native counter and inside the aggregate counter.
- B tokens are only residual tokens after reserving one intact selector request. Reserve the worst allowed ASCII JSON B entry (32,768 bytes), 512 framing bytes, the actual selector prompt/A entry, 2,000 completion tokens, and the normal prompt margin max(64,ceil(0.05*prompt_bound)). Pin exactly how bytes are converted to a conservative prompt-token bound; prefer the established byte upper bound. Completion is added once. Include actual role/system/tool schema framing in the bound or separately prove the declared 512-byte allowance covers it.
- A and B entries each have an exact 32,768 ASCII-byte limit. Serialize canonically with ensure_ascii=True and allow_nan=False before measuring; escaping/metadata count. Nothing is truncated, compacted, summarized or silently omitted to fit. Recheck actual intact selector admission after B against reserved and actual residual budgets.
- Any nonfatal actual released A remains the fallback, including prose, null, honest limitation, source-withheld output and ordinary known-budget abstention. Missing execution metadata is not a fabricated final program or a source contradiction. B is selectable only when its actual released result binds its surviving final execution, own immutable workspace and later original automatic source check. Never select computed-but-withheld revision.final.
- Exact finite JSON answer agreement keeps the entire A outcome; it does not use scorer equivalence. Otherwise a single tool-free selector can choose an existing B only when its strict shared-requirements schema is valid, every B requirement is supported, and at least one A requirement is contradicted. Unknown, not_found, ties, malformed output or absent evidence cannot invent a contradiction. Preserve B's original honest limitation in packet and selected released output.

Priority 1: preserve A's actual policy (actual Single loop, paired deterministic inputs)
P01 Request-prefix parity: give standalone Single and H2 A identical synthetic packet and native responses, including retrieval, inspect, final execution, post-final tool continuation and final prose. Assert identical message/tool schemas, request options and sequence before A returns; no V6 boundary message, extra budget prompt, new system instruction, reduced cap or forced explicit-final policy appears. Compare usage and Base-normalized released answer/evidence/limitation/error. First successful mode=final must not trigger early handoff.
P02 Natural source revision: first original check reports an issue, then actual Single continues, executes a distinct corrected final and passes the second check. Assert identical feedback, two automatic checks charged inclusively, exact released endpoint and revision diagnostics. A feedback attempt without a distinct revised candidate is not labeled a completed source revision.
P03 Genuine fallback matrix: use actual loop paths for prose-only final, finite null, non-null limitation, known token refusal, tool exhaustion before source check, iteration exhaustion, and computed final withheld by source issues. Assert H2 preserves precisely A's normalized endpoint/error when auxiliary work is skipped or fails nonfatally, rather than clearing evidence, removing limitation, manufacturing null credit or substituting revision.final.
P04 End-of-budget A: A uses all 30 calls, 30 tools or tokens. Assert no B/selector/prefetch, same A result, no extra tool charge. A usage above the true aggregate cap or unknown usage instead fails the whole result with an accounting error, never a Budget-exceeded abstention.

Priority 2: residual admission, accounting and initialization
L01 Inclusive boundaries: parameterize C_A=26,27,28,29,30 and R_U=0,1,2,3,4. B starts only with >=2 B slots and >=3 tools. At R_U=3, initialization consumes one and actual B has two inclusive tools; it may naturally fail to finish. C_A=27 allows B at most2 calls plus selector1. No 25+2 source-check reserve, no 28-tool primary cap, and no hidden extra SDK turn.
L02 Starting-packet exactly once: instrument actual B get_starting_packet (or existing perturbation equivalent). On success, initialization failure before SDK, and failure after a partial local initialization, assert exactly one invocation/host charge, zero duplicated prefetch, correct aggregate U_A+1+U_B, and unchanged A fallback. If B never starts or entry is refused, both invocation and charge are zero. Distinguish charged initialization from model tool requests in audit.
L03 Exact adoption once: inject known usages with nonzero prompt/completion/cost/cached counts across A, B, selector; assert totals, per-call records and each phase sum exactly once. Repeat adoption/reuse should be rejected, not silently doubled or reset. Explicit reported zero remains known; cost=None propagates. Duplicate IDs across independent contexts must not merge billing records.
L04 Unknown and malformed ledgers: admitted failure with usage_available=False, missing usage=None, malformed counters, bool/negative/nonfinite counters, inconsistent aggregate/per-call totals, and non-JSON objects. Preserve raw tagged diagnostics/unknown markers and any verified counters; cost remains unknown. Whole result is terminal accounting failure even after a correct A. Never synthesize a known zero/free attempt, hide it in fallback or use a Budget-exceeded prefix that Base suppresses.
L05 Refused versus attempted calls: a local preflight refusal changes neither actual send count nor known usage; an admitted provider failure counts its request/attempt even if no response trace exists. A known-usage provider error can preserve A when the selected policy permits nonfatal fallback, retaining cost and error diagnostics; unknown usage is fatal. Test third-attempt failure/selector exception and retain every first attempt. Safe journal send evidence is separate from controller invocation count.
L06 Actual overshoot: A, B or selector reports one token above phase/global admission or exceeds aggregate calls/tools due a faulty integration. Assert whole fatal outcome with exact diagnostic counters, rather than clamp, drop last call or release A/B. Also test one-token-below/exact-cap legitimate boundaries.

Priority 3: B independence and released execution/source ownership
B01 Fresh trajectory: A mutates its packet, workspace and tool result; B starts from its own original packet with the ordinary prompt/retrieval/feedback, no A messages, code, selected records or source feedback. Same resource IDs with deliberately different synthetic values must not cross-contaminate. Capture defensive workspace snapshots and phase-qualified tool IDs; B mutation cannot alter saved A artifact or selector packet.
B02 Natural continuation and source feedback: B executes a final, then performs another retrieval/inspect/final and one ordinary source revision. Assert original Single invalidation rules and real automatic checker, no first-final interception. Its executed candidate/workspace/citations/check are bound to the final actually released by Base.
B03 Withheld/malformed B: final source issues, missing final computation, overwritten artifact, inspect-mode reply, error/error_type, mismatched code/answer/limitation/evidence, stale workspace hash, wrong check citations, pre-execution check, missing/duplicate/foreign tool ID, mismatched native request/reply and source-check exception. Assert B cannot be selected even if revision.final contains a plausible computed answer; exact A fallback remains. Use ordinary frozen source semantics rather than introducing stricter semantic gates.
B04 Honest limitations and empty results: a valid released B with limitation, supported finite null/0/false/[] and permitted empty evidence remains faithfully represented. Do not inherit V6's absence-of-limitation eligibility veto or treat False==0/None==[] as exact agreement. Never remove a limitation to make B admissible. Also test actual nonfatal A with no execution metadata: expose missing provenance honestly and never synthesize an A program or classify absence alone as contradicted.
B05 Retrieval-request metadata: only actual successful retrieval requests belong in the selector entry; preserve exact request scope and candidate ownership. Include successful empty retrieval, failed retrieval, repeated identical calls, long escaped arguments and a retrieval after prior final that invalidates it. Metadata is evidence of what was requested, not proof of exhaustive search or semantic correctness.

Priority 4: intact selector reservation and strict decision rule
S01 Byte boundaries: A and B entries at 32,767/32,768/32,769 serialized ASCII bytes, plus Unicode/control characters/quotes/backslashes/long IDs/code/limitation/retrieval metadata. Boundary counts must include actual serialization and the complete entry. Oversize A skips auxiliary work if intact selection is impossible; oversize B preserves A and retains already-spent B usage. No shortened program, citation list, metadata or hidden truncation.
S02 Worst-case reservation: independently calculate the upper bound with max-size escaped B entry, actual A/system/question/schema and framing; test just-below/exact/just-above token admission, ceil rounding around 5%/64 crossover, completion2000 added once, and lower caller cap. Actual B completion reduces residual; actual intact selector request must still fit. If tokenizer/counting says it exceeds the proven bound, refuse selector safely with diagnostics; never compact candidate entries or borrow future tokens.
S03 Exact agreement: canonical finite JSON strict cases: false vs0, true vs1, null vs[], "1" vs1, [1,2] vs[2,1], duplicate list values and 1 vs1.0. Object key order should follow the pinned canonical rule. Agreement releases the entire original A including its evidence/limitation and makes no selector request; typed scorer normalization is absent from routing.
S04 Strict response parser/rule table: valid choiceB with all B supported + at least one A contradicted is the sole switch case. Cover A/UNKNOWN, allA/Bsupported, A not_found only, one B not_found/contradicted, missing/extra/duplicate requirement, unequal A/B requirement IDs, invalid status/choice/case/aliases, empty requirements, blank reason, extra confidence/answer/program fields, duplicate JSON keys, Markdown/prose prefixes, multiple objects, NaN/Infinity and malformed response. Invalid/unsupported/tied responses keep exact A and retain selector usage; no repair retry. Native selector tool_calls are rejected even with apparently valid JSON content.
S05 Existing-candidate binding: tamper selector A/B program/artifact/source summary/workspace/program digest/retrieval metadata; ensure a response cannot release a third answer, new code, computed-withheld B or a candidate from another attempt. Source summaries must bind the actual raw original checks; conflicting error plus issues=[] cannot certify source support. Tool-free selector messages/audit contain intact entries and honest limitations.
S06 Selector failure/fatal distinction: known pre-admission refusal or malformed selection keeps A; known billed failure retains usage and A under the declared policy; unknown usage and actual overshoot are globally fatal. Assert raw diagnostics distinguish unstarted B, init failure, B exhausted/ineligible, agreement, selector refusal/error/malformed/UNKNOWN, switchB and whole-fatal loss.

Priority 5: worker, storage, native transport and provenance
I01 End-to-end synthetic dispatch: actual selected job dispatcher -> actual H2 -> actual Single loops -> Base -> run_agent_safe/parse_outputs -> worker gzip externalization -> restore. Cover A-only, eligible B agreement, selected B disagreement, source-withheld B, prose A fallback and auxiliary fatal. Assert saved released row, error, canonical usage, full trace and both owned workspaces round-trip exactly; first-attempt IDs/identity and audit SHA/CRC/owner remain correct. No disk spill is required for an intentionally unsaved interactive job; saved evaluated runs must match their declared gzip identity.
I02 Serialization and journal: exercise actual native SDK request encoding with offline mock transport/send; reject arbitrary host boundary objects, retain audit-only annotations, and preserve JSON role/content/tool-call schemas after source feedback/compaction. Assert frozen model/profile/reasoning_effort/timeout/retry/completion cap/native HTTPX2 options and raw usage=None versus explicit zero are unchanged. Pair safe SDK journals by actual request IDs; count retained terminal failures and legitimate missing responses honestly.
I03 Source equality/provenance: compare exact bytes of shared SingleAgent, Base, semantic guide, tools/checker, worker, helpers, scorer and public provider functions against the selected common baseline; only prespecified additive H2/dispatch/test/docs changes are allowed. Any common accounting change needs an explicit same-control change/fresh freeze rather than an unnoticed helper patch. Freeze strategy dispatch, all source/runtime files, credential-free public binding, input/split hashes and actual default options before a large run; tests must never invoke real Settings or credential setup.

Reporting requirements
Test diagnostics must keep A source-feedback/check-attempt counts, completed A source revisions, B source revisions, exact answer agreement, eligible B, selector decisions, selected-B effects and auxiliary fatal losses distinct. A generic revised flag is not an independent repair. No test chooses policy using gold correctness or confidence; synthetic expected outcomes only validate mechanics. Source-valid execution is provenance, not semantic truth. Provider invocation/request/response/journal counters may have explained gaps on failures, never invented equalities.

Minimum implementation acceptance packet
Provide focused test names/log and exact module/source hashes, with all policy/cap/ownership/fallback/reservation negative cases above covered by parameterized fixtures. Include at least one real-loop A parity test, one real-loop B source-withholding test, one actual native SDK encoder mock and one actual worker/gzip roundtrip. No live check or accuracy claim is needed to accept the offline implementation. A later reserved-development live interface check, frozen paired subset, terminal integrity audit and unchanged scoring remain separately root-owned.
