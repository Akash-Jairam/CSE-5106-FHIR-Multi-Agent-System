Primary/fallback
Require existing explicit executed final on exact workspace hash, no primary/source/global errors and no unresolved scope. Freeze source records, artifact, context and retrieval ledger before critique. Primary with failed gates is not rescued. Critic tools execute on separate copies; primary lineage and final_check_issues stay untouched. Any nonfatal schema, token refusal, inspect, patch, final or source-check failure retains primary and appears in auxiliary diagnostics. Fatal accounting returns no released answer. No answer-kind, family, question-ID, template-ID or model-ID routing.

Input packet
Original parsed context(question, patient_fhir_id, current_time, assumptions), intact actual final_code and code_sha256/workspace_sha256, full retrieval ledger/completeness flags and unresolved_scope, plus inventory by resource type(count and at most1 source example each). Examples are explicitly previews; no completeness inference. The exact code/ledger/context must fit unchanged or skip. Rendered primary answer/evidence/operation prose are omitted; code can expose values, so no independence/blindness claim. Shared semantic guide is unchanged.

Finite strict JSON
Reject duplicate keys, nonfinite JSON, unexpected keys, booleans where integers required, deep/oversized structures, tool calls in either response. Every bounded string is nonempty after stripping except new_text, which may be empty for deletion.
Anchor={channel:'question'|'assumptions',quote:'unique exact original substring'}; host derives/saves its span; missing or ambiguous quotes (including overlapping repeats) are rejected. The model supplies no character indices. Anchoring proves provenance only. Max quote2,000 characters. The patch channel+quote must equal the first claim anchor.
Call1 KEEP/UNKNOWN={decision:'KEEP'|'UNKNOWN',reason:string<=1,000}.
Call1 INSPECT={decision:'INSPECT',anchor:Anchor,claim:string<=1,500,inspect_code:string<=6,000}. Only one focused factual probe; original-question obligation and observable program discrepancy, no desired answer key.
Host tool1 execute_python_code(mode='inspect') on frozen copied workspace. Its answer must be exactly:
{facts:[Fact,...],observations:[{name:string<=80,value:finite_JSON},...]}
Fact={resource_id:'Type/id',field_path:'concrete.path[0]',value:finite_JSON};1..16 facts;1..16 uniquely named observations; each fact/observation serialized value<=1,024 chars. Host validates each Fact against actual immutable original source fields using typed finite JSON equality. Inspection answer<=1,500 tokenizer tokens; otherwise skip, not silently trim required facts. Full tool output/stdout retained in audit. Observations are actual PROBE outputs, not guaranteed original-program traces or trusted semantic oracles; the model can compute a literal. The host binds execution and source facts, not causal truth, and arbitrary model-written assertions do not become proofs.
Call2 KEEP/UNKNOWN has same minimal shape.
Call2 PATCH={decision:'PATCH',anchor:Anchor,observed_discrepancy:string<=1,500,expected_obligation:string<=1,500,preserved_obligations:[string<=500,...] (1..8),witnesses:[Witness,...] (1..8),patch:{old_text:string<=8,000,new_text:string<=8,000}}.
Witness={fact:Fact,observation_name:string<=80,observed_value:finite_JSON,relevance:string<=500}. Every fact must exactly occur among validated probe facts and original records; every observation name/value must exactly match the actual probe answer. New semantic explanation is fallible, not accepted as an oracle. Unique nonempty old_text must occur exactly once in actual original code, including overlapping occurrences; old/new must differ, full new code<=32,000 chars and parse as Python. Exact replacement is a generic bounded region, no repair grammar/templates. Textual locality does not guarantee semantic locality.

Candidate and final check
Tool2 executes the entire actual patched program(mode='final') once on the unchanged frozen workspace. Host uses ordinary worker/AnalysisAgent._draft metadata validation; no correction call. Require a substantive executed change in answer, evidence or contributing_ids; operation prose alone is not a repair. Same contributors with changed projection/grouping is allowed; do not require changed IDs.
Tool3 re-fetches candidate evidence with original check_fields(question/current_time/patient), including persistent unresolved-scope gate. Reject all raw/global issue strings plus per-citation invalid/warning results and malformed/incomplete results. Candidate-specific empty handling uses the NEW explicit final: no-evidence false/zero/[] are allowed per ordinary established-empty rule, null per existing policy; nonempty/non-null needs evidence. There is no prefer-nonempty branch or semantic guarantee for null. Candidate limitation means inability to establish full repair and preserves primary. No inspection/proposed patch is ever released as answer.
Release policy label executed_source_checked_critic_proposal; assurance explicitly fallible_model_semantics_not_global_proof. Record primary, exact packet hashes, both responses/usage, full probe/result, validated facts, exact patch, alternate, source check, all errors and rationale. Frozen workspace hash rechecked before/after each stage. Counts:0 tools for KEEP/UNKNOWN;1 for inspected nonrepair;2 for failed candidate;3 for candidate source check. Every real sandbox/check is charged. No implicit or hidden extra work.

Evaluation/portability
Core interface is task context+program+source handles+probe+patch, with FHIR source/scope adapter. No empirical cross-model/other-task claim. Development300 is adaptive; freeze ONE checkpoint before once-only question-disjoint confirmation in final2931. No untouched patient-disjoint cohort is available and no new-patient claim is made. No unseen questions/gold/reference programs are read during implementation.

Coverage limit: this first candidate requires positive immutable source facts. Context-only discrepancies without such facts remain UNKNOWN; no new typed-provenance gate is introduced.

Source-check envelope is fail-closed: only issues/results/n_valid/question_scopes/scope_membership_only keys are admitted; contradictory raw error/failure fields are rejected even if citation results look successful. Escaping exceptions after admission to an actual model invocation mark accounting fatal; preflight serialization/tokenizer exceptions preserve primary.

Both reported completion subcaps (1,800 and 4,000) are fatal if exceeded even when total phase/global usage remains below its ceiling. Each admitted invocation must return one canonical per-call usage record with typed nonnegative counts, usage_available=True, and consistent aggregate counts. Unknown/malformed records retain reported numeric counters where available, mark unavailable placeholders explicitly, and are globally fatal rather than auxiliary fallback.

Optional canonical cached-token counts must also be typed nonnegative integers. Invalid cached/per-call fields become explicit unavailable placeholders, and malformed aggregate shapes restore earlier known totals rather than escaping the shared output formatter. Valid reported numeric increments are retained.

The canonical boundary also rejects nonfinite/negative optional cost, inconsistent optional cached aggregates, and unexpected per-call keys. Fatal-path per-call records retain only safe canonical numeric counters plus explicit unavailable/malformed flags so output serialization cannot destroy the accounting audit.
