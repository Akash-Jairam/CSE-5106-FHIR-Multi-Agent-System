Executable critic feasibility review (read only; 2026-10-15)

Recommendation
Use the unchanged V3 LedgerSolver allocation (175,000 tokens, 27 tools) and a fresh critic phase (25,000 tokens, at most 3 tools). Start with a frozen-workspace critic, without supplemental retrieval. It is an experimentally defensible model-mediated repair protocol, not a mechanically proved semantic repair.

Why frozen workspace
LedgerSolver._handle_tool_call invalidates any prior final before every retrieval, including failed retrieval. ScopedLedgerToolbox also changes original-record/scope-completeness state. If a critic retrieves a newly relevant record and replacement fails, the old computation can be stale or its completeness premise contradicted. Preserving it automatically would bypass the existing execution contract. A read-only copied workspace avoids that conflict. It cannot fix missing retrieval; report that as UNKNOWN and preserve the validated primary.

Concrete protocol
1. Validate the same V3 primary release gate first: explicit final artifact, exact workspace hash, successful complete final tool batch, no original source-check issues, no fatal accounting error. Freeze the primary artifact, workspace, context, retrieval ledger, complete types and unresolved scope. A critic never rescues a primary that failed this contract in this candidate.
2. Call the critic once with original question/context, intact final code and its hash, workspace hash, complete-type/scope facts, retrieval ledger, and bounded source inventory. Hide the rendered answer but state that code can reveal it: this is not a fully blind independent verifier. No question ID, template ID, reference answer/program, previous run score, or benchmark-derived repair classes enter this packet. If the intact code/essential metadata cannot fit a predeclared packet token cap, preserve the primary and record a coverage skip.
3. The first response is KEEP/UNKNOWN or one focused inspect request plus a concrete claimed mismatch. An inspect request is the only model-requested tool allowed. Host forces execute_python_code mode=inspect and executes on a deep copy of the frozen workspace. All retrieval, final execution, check_fields, auto mode and extra batched requests are rejected. Count the one actual sandbox invocation; bound its model-visible reply and retain its full audit.
4. After a successful inspect, call the critic once more, with no tools, for KEEP/UNKNOWN or one patch. Require an exact quoted original question/context span, a concrete behavioral mismatch, actual source-field witnesses, and one old/new code region. Validate the span text against the original channel, witness resource IDs/field paths/values against the immutable held original records, and exact unique old-text occurrence against the actual primary code. Bound both patch strings and total replacement size. This is generic text/code lineage validation; do not resurrect predicate/rank AST templates or question-family routing. Textual anchoring establishes provenance only.
5. Tool 2: host splices the bounded patch into the actual original program and runs the entire patched program once in mode=final, with a fresh copy of the original frozen workspace. The model's prose answer is never released. Validate the executable metadata through the existing final contract/AnalysisAgent._draft. Do not give a failed candidate a free extra execution or metadata correction.
6. Tool 3: host calls the existing original-source checker for the executed candidate with the original question/patient/current_time and the unchanged unresolved-scope gate. Reject every raw/global source-check error as well as individual citation/scope issues; field_check_issues alone omits some raw global errors. Apply the established-empty rule to the new executed candidate, not solver.final_computation still pointing at the primary. A source-valid null still requires honest absence/completeness interpretation; source checks do not prove that interpretation.
7. Release the alternate only after all candidate gates succeed and the critic supplied an explicit, supported mismatch rather than vague doubt. Every nonfatal auxiliary parse, budget, probe, patch, execution, or source-check failure preserves the already valid primary. Record unsuccessful auxiliary checks separately, without converting them into final_check_issues that veto the primary. Unknown billed usage or aggregate/phase overshoot remains fatal for the entire attempt; never clear it as an auxiliary error.

Tool/model accounting
The paths are zero tools for KEEP, one tool for inconclusive inspection, or exactly three tools for an attempted replacement. No replay, retrieval, field validation, final correction, or synthesis may be hidden inside an additional host call. In-memory hash/span/source-path validation is not an external tool. Existing final artifact lineage makes a mandatory second original-program execution unnecessary. If a replay is used inside the one inspect program, disclose that composite code and audit it; do not claim a generic model-generated replay proves semantics.
Use an explicit two-model-call controller. Role.run(max_turns=1) can already make a second synthesis call after a tool; max_turns=2 can make a third. The 25,000 cap includes every input/output token across both calls, including repeated packet and inspect output. Cap the initial packet by actual tokenizer count and reserve enough budget for the complete second input and patch output. An auxiliary local budget refusal preserves primary; unknown provider usage does not.

Existing API locations
- agent/query_contract_agent.py: PhaseHost, LedgerSolver, ScopedLedgerToolbox, QueryContractAgent._execute/_trace_tool/_targeted.
- agent/single_agent.py: _computed_candidate, _handle_tool_call, _automatic_check and _check.
- agent/framework.py: Toolbox.call computation invalidation; Role.run implicit final synthesis; _bound_tool_reply for previews.
- tools/python_executor.py and tools/python_worker.py: each sandbox starts fresh, copied task resources only, OS network/file isolation, 60s cap; mode=inspect cannot certify a final.
- agent/analysis_agent.py: _draft checks executed answer and metadata contract.
- agent/verification_agent.py: field_check_issues is not a replacement for checking all raw checker errors.

Assurance and generalization limits
The host can prove exact lineage, original source-field values, executable metadata, fixed workspace, bounded work and successful original-source checks. It cannot generically prove that the natural-language obligation is interpreted correctly, that all relevant records were fetched, or that a witness establishes the complete causal effect of the patch. A model can identify a true local discrepancy and still introduce a wrong fix, compensate with unrelated arithmetic, or choose the wrong clause. Label the release as an executed/source-checked critic proposal, not semantic proof. Preserve the original candidate, alternate, witness, patch, tool results and acceptance reasoning so harmful revisions are measurable.

For generality, keep CriticCore about task context, source handles/field paths, executable artifact, inspection capability, patch and release status. FHIR-specific scope/schema/source validation belongs in a TaskAdapter. Use ordinary role/content JSON plus declared tools, not model-family-specific hidden reasoning. Do not introduce literal dates, clinical concepts, expected answer shapes, benchmark IDs or observed failure-class branches. Evaluate total accuracy, harmful/helpful revision counts, critic coverage and cost, including patient-disjoint unseen questions before promotion. Repeated fixed300 results are development evidence, not an unbiased generalization estimate; no cross-model claim is justified without later cross-model evaluation.

Current engineering blockers before implementation freeze
- Specify finite schema/size caps and exact two-call token reservation.
- Make candidate source-check error aggregation match the existing raw issue/scope rules, including new-candidate empty handling.
- Decide and document that semantic release remains a fallible model judgment. No generic code/witness format alone eliminates that uncertainty.
- Freeze the untouched holdout selection and promotion criteria before any unseen content/labels are opened.
